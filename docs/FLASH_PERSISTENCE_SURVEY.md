# SMSL DO400 PEQ 本体保存（SPI NOR Flash 永続化）調査レポート

本ドキュメントは、SMSL DO400 純正 FW 3.23（XMOS XU316 Tile 0）の逆アセンブル調査に基づき、PEQ 設定をオンボード SPI NOR Flash（ZB25VQ16 / 2 MiB）へ保存・電源オン時自動復元するための技術的条件・注意点・設計案をまとめたものです（未実装・調査記録）。

---

## 1. 調査結論

- **実装可能性**: 高い。純正 FW 3.23（Tile 0）に XMOS `libquadflash` の主要 API がすべてリンク済みであり、自前の QSPI ビットバンギングドライバは不要。
- **最大の注意点（最重要発見）**: 純正の `p_qflash` は **`CLKBLK_3`（I2S 音声クロック生成と共有）** を指定しているため、そのまま音楽再生中に呼ぶと I2S クロックを停止させてしまう。一方で **`CLKBLK_1` は Tile 0 上で完全未使用** であり、QSPI ポート 3 本も完全非共有のため、独自ポート構造体で `CLKBLK_1` を渡すことで音声・USB と 100% 非干渉に Flash へアクセスできる。
- **ブート破損耐性**: `WRSR`（Status Register 書込）は Tile 0 にリンクされておらず、ZB25VQ16 の QSPI ブートに必須な `SR2 = 0x02 (QE = 1)` を誤消去する経路がない。

## 2. 純正 FW 3.23（Tile 0）内の既存 Flash 資産

### 2.1 フラッシュ定義テーブル（`dp[0x00]` = `0x8B220`）
`fl_QuadDeviceSpec flash_devices[3]`（1 エントリ `0x70` = 112 B）の先頭エントリが実機チップ **ZB25VQ16** に完全一致。

| 項目 | 値 |
|---|---|
| JEDEC ID (`idValue`) | `0x00BA6015`（ZB25VQ16） |
| ページサイズ (`pageSize`) | `0x100`（256 B） |
| 総ページ数 (`numPages`) | `0x2000`（8,192 ページ = 2 MiB） |
| セクタサイズ (`regularSectorSize`) | `0x1000`（4 KiB / 512 セクタ） |
| 消去コマンド (`sectorEraseCommand`) | `0x20`（4 KiB Sector Erase） |
| 書込コマンド (`programPageCommand`) | `0x02`（Page Program） |
| 読込コマンド (`readCommand`) | `0xEB`（Quad I/O Fast Read） |
| WREN / WRDI / RDSR | `0x06` / `0x04` / `0x05`（WIP mask = `0x01`） |

### 2.2 既存 `libquadflash` 関数アドレス（Tile 0、すべて single-issue）

| アドレス | 機能 | 備考 |
|---|---|---|
| `0x86508` | `fl_connectToDevice(ports, spec, n)` | 任意の `fl_QSPIPorts*` を受け取り `dp[0x14F2..0x14F5]` へコピー。JEDEC 照合後 `spec*` を `dp[0x157E]`（`0x90818`）へ格納。`WRSR` は呼ばない |
| `0x86624` | `fl_disconnect()` | `0x882E4` を呼び、CS High 確定後に使用した QSPI ポート 3 本とクロックブロックのみ `INUSE_OFF` 化 |
| `0x86830` | `fl_readPage(addr, buf256)` | `0x88594` で 256 B Quad 読込。内部でバイト毎ニブル入替を実施 |
| `0x866E0` | `fl_eraseSector(sectorNum)` | `WREN` → `0x20`（4 KiB 消去）→ WIP 待機 → `WRDI` |
| `0x867C0` | `fl_writePage(addr, buf256)` | `WREN` → `0x02`（256 B 書込、内部で対称ニブル入替）→ WIP 待機 → `WRDI` |
| `0x86864` | `crc32` ヘルパ | XS3A ハードウェア `crc32` 命令を使用（多項式 `0xEDB88320`） |

> **ニブル順序の対称性**: `0x88594`（読込）と `0x886D0`（書込）の双方が対称にニブル入替を行うため、`fl_writePage` で書いた 256 B は `fl_readPage` で同一バイト列として復元される。

## 3. ハードウェア資源・競合監査（Tile 0）

### 3.1 クロックブロック使用状況

| クロックブロック | リソース ID | 純正 FW 3.23 での用途 | 競合判定 |
|---|---|---|---|
| `CLKBLK_REF` | `0x00000006` | システム基準クロック（100 MHz） | 共有基準 |
| **`CLKBLK_1`** | **`0x00000106`** | **完全未使用（バイナリ内 0 参照・`getr` 0 件）** | **安全（専用化可能）** |
| `CLKBLK_2` | `0x00000206` | I2S MCLK（`0x8EB9C`） | 使用中 |
| `CLKBLK_3` | `0x00000306` | **I2S BCLK/LRCLK（`0x8EBA0`）兼 純正 `p_qflash`（`0x8B37C`）** | **危険（再生中競合）** |
| `CLKBLK_4` | `0x00000406` | USB XUD（`0x8EB80`） | 使用中 |
| `CLKBLK_5` | `0x00000506` | USB XUD（`0x8EB84`） | 使用中 |

### 3.2 QSPI ポート使用状況
純正 `p_qflash`（`0x8B370`）の 3 ポート：
- `XS1_PORT_1A`（`0x00010000`）: QSPI CS
- `XS1_PORT_1B`（`0x00010100`）: QSPI SCLK
- `XS1_PORT_4B`（`0x00040100`）: QSPI SIO

いずれも Tile 0 の音声・USB コードからは参照されておらず、完全専用。よって独自構造体
`{ 0x00010000, 0x00010100, 0x00040100, 0x00000106 }`（`CLKBLK_1` 指定）を `fl_connectToDevice` へ渡すことで、**I2S・USB とハードウェアレベルで完全独立**した Flash 読み書きが可能。

### 3.3 スレッド排他・純正 DFU との両立
- WebHID `PEQ1` フック（`0x80908`）と USB DFU ディスパッチャ（`0x84E20` / `0x85078`）は**同一の EP0 スレッド（`0x8072A`）**で動作するため、スレッド競合は発生しない。
- 純正 DFU の Flash オープン状態フラグは `dp[0x14FD]`（`0x90614`）。
  - PEQ 側で Flash 操作する際は `dp[0x14FD] == 0` を事前確認し、非ゼロなら `ERR_BUSY` で即拒否する。
  - PEQ 側の操作完了時は毎回即 `fl_disconnect()` を呼び、`dp[0x14FD]` は変更しない（純正 DFU が後から実行されても `flash_cmd_init()` が正常に再接続する）。

## 4. 推奨 Flash マップ・データ構造・容量見積り

### 4.1 2 MiB SPI NOR Flash マップ
実機ダンプ（`do400_dump.bin`）の `0x060000..0x1FFFFF`（1,664 KiB）は全バイト `0xFF`（未使用）であることを確認済み。

| アドレス範囲 | セクタ番号 | 用途 |
|---|---|---|
| `0x000000..0x02DFFF` | 0..45 | ブートローダー＋Factory Image 0（純正・絶対非接触） |
| `0x02E000..0x05F0FF` | 46..95 | Upgrade Image 1（PEQ FW、512 KiB 上限でも最大 `0x0AE000` まで） |
| `0x060000..0x1FDFFF` | 96..509 | 未使用（全 `0xFF`） |
| **`0x1FE000..0x1FEFFF`** | **510** | **PEQ 永続化スロット A（4 KiB）** |
| **`0x1FF000..0x1FFFFF`** | **511** | **PEQ 永続化スロット B（4 KiB）** |

- **DFU 更新との分離**: USB DFU の消去・書込領域（最大 `0x0AE000`）と 1 MiB 以上離れているため、将来の FW 更新後も PEQ 保存設定は消えない。
- **電源断耐性 & ウェアレベリング**: スロット A / B へ交互に書き込み、CRC32 検証を通過した最大世代番号（`gen_seq`）を採用する。1 セクタ公称 10 万回 × 2 面 ＝ 20 万回（毎日 10 回保存で約 54 年）。

### 4.2 全 6 サンプルレート同時保存（PC レス自動追従）
Q29 Biquad 係数はサンプルレート `fs` に依存するため、対応する全 6 PCM レート（`44.1 / 48 / 88.2 / 96 / 176.4 / 192 kHz`）を 1 スロットへ一括保存する設計が最も合理的。

- ヘッダ（64 B）: `magic ('PEQS')`, `version (1)`, `gen_seq`, `pcm_on`, `pcm_mask`, `pcm_preamp_q28`, `rate_mask`, `crc32`
- 係数テーブル: `6 rates × 10 bands × 2 ch × 5 taps × 4 B` = **2,400 B**
- 合計: **2,464 B**（256 B × **10 ページ = 2,560 B < 4,096 B**）
- 1 回の保存所要時間: 4 KiB 消去（約 45 ms）＋10 ページ書込（約 8 ms）≒ **約 55 ms**（USB HID 制御転送 5 秒タイムアウトに十分収まる）
- 同一内容スキップ: 直近保存データと CRC32・内容が完全一致する場合は消去・書込をスキップ。

### 4.3 Tile 0 メモリ & DFU コンテナ容量
- **Tile 0 SRAM**: `init_SP = 0x000FFF78`（512 KiB SRAM、空き 435 KiB 超、`dp[...]` 直接アドレッシング可能領域も `0x9302C..0x9B21C` に 32 KiB 以上あり）。6 レート用 RAM キャッシュ（2,464 B）は未初期化 BSS に配置すれば **DFU `.bin` のサイズ増加は 0 B**。
- **DFU コンテナ容量**: 現行 200,896 B（196.19 KiB）に対し、追加コードは約 1〜1.5 KiB 見込みのため、**約 197.7 KiB < 200 KiB（純正 FW 3.23 からの 1 回 DFU 上限以内）** に収まる見込み。

### 4.4 起動時ロード位置 & フォールバック
- **フック候補**: EP0 スレッド初期化直後（`0x807A4` の `DFUReportResetState` 呼び出し付近）で 1 回だけ実行。
- **検証ルール**: 両スロットの先頭ページ〜10 ページを読み、1) `magic == 'PEQS'`、2) `version == 1`、3) `crc32` 一致、4) `pcm_on ∈ {0,1}`・`pcm_mask <= 0x3FF`・`pcm_preamp_q28 <= 0x20000000` をすべて満たす最大 `gen_seq` スロットのみ RAM へ復元。どちらも無効・未書込なら **Flat / OFF で安全起動**。

## 5. 将来実装する場合の推奨検証ステップ

1. **オフライン (`xsim`)**: QSPI 読み書き層を RAM モックに差し替え、A/B 世代選択・CRC32 破損フォールバック・6 レート自動切替・DoP 保護との両立を全テスト。
2. **実機ステップ 1（読み取り専用テスト）**: 音楽再生中に `CLKBLK_1` 経由で `0x1FE000` を読むコマンドだけ実行し、音切れ・エラーゼロかつ `0xFF` が返ることを確認。
3. **実機ステップ 2（書込＋電源再投入テスト）**: 「本体へ保存」→ 電源オフ／オン → ブラウザ未起動のまま PC／スマホ接続で PEQ 復元＋サンプルレート変更時の自動追従を確認。
